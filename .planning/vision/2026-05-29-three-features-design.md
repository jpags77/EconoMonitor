# Design: EconoMonitor — Time-Series, Index Ticker, Market Explainer

## Problem Statement

EconoMonitor scores daily macro conditions and synthesizes them into an
environment label, action bias, and per-asset guidance. Three additions:

1. **Quantitative time-series** of daily dimension scores, ML-ready, with oil
   and inflation tracked as separate dimensions (today they're one combined signal).
2. **Floating index bar** (S&P 500, DJIA, Nasdaq) always visible on desktop.
3. **Market-vs-macro explainer** — an LLM commentary box that rationalizes recent
   market index movements against the prior ~month of EconoMonitor scores.

## What I Found (existing state)

- `macro_entries` (Supabase) already is a daily time series: `raw_signals` (5 dims),
  `macro_score` (0–100), and per-day index closes inside `key_metrics`
  (sp500/djia/nasdaq/oil_wti/gold/vix/treasury_10y), plus narrative fields.
- Daily Vercel cron → `/api/generate` (Bearer `CRON_SECRET`) → Tavily articles +
  Claude Sonnet (`web_search` for spot prices) → inserts one row.
- Dashboard `app/page.tsx` (force-dynamic SSR) reads last 30 rows.
- Scoring: `lib/score.ts normalizeScore(rawSum)` assumes 5 signals, range ±10.
- LLM: Anthropic Claude for generation; OpenAI gpt-5-nano for chat.
- Available keys: Anthropic, OpenAI, Supabase, Tavily, NVIDIA. **No market-data key.**

## Premises (confirmed)

1. Splitting `inflation_oil` into `inflation` + `oil` **reweights the composite**
   (that theme goes 1/5 → 2/6) and creates a **schema discontinuity**: pre-split rows
   are 5-signal/±10, post-split 6-signal/±12, and the old combined signal cannot be
   decomposed backward. Stamp `schema_version`; `macro_score` is comparable only within
   a version. ML training uses per-dimension `raw_signals`, not the baked composite.
2. No market-data API key exists; a true live ticker would need a new dependency and
   free tiers often expose only ETF proxies (SPY/DIA/QQQ), not real indices.
3. Feature 3 consumes Feature 1's history → build order **F1 → F3**; F2 independent.

## Decisions (locked)

| Fork | Decision |
|------|----------|
| F1 data model | **Extend `macro_entries`** — split signal, add `schema_version`, add a SQL view flattening `raw_signals` to numeric columns for ML export. One write path. |
| F2 ticker source | **Daily snapshot** from existing `key_metrics` (free, ships now; static once-a-day bar, not live intraday). Live quotes deferred. |
| F3 timing | **Daily cron, stored** — one extra Claude call/day inside `/api/generate`, persisted in a new column, rendered instantly. |

## Recommended Approach

### Feature 1 — Split signal + ML-ready series
- `RawSignals`: replace `inflation_oil` with `inflation` and `oil` (each `SignalScore`).
- `lib/score.ts`: make `normalizeScore` signal-count-aware (normalize by `count × 2`)
  so both 5- and 6-signal rows map to 0–100 correctly.
- `macro_entries`: add `schema_version int not null default 2` (v1 = 5-signal legacy,
  v2 = 6-signal). New inserts write v2.
- Claude prompt (`lib/claude.ts`): emit 6 signals with separate oil and inflation
  scoring guidance.
- SQL view `daily_scores_v` flattening `raw_signals` keys + `macro_score` + index
  closes into numeric columns, filtered to `schema_version = 2`, ordered by date —
  the ML export surface.
- UI: update dashboard subtitle and any signal-label rendering to list 6 dimensions.

### Feature 2 — Floating index bar (desktop)
- New `components/IndexTicker.tsx`: fixed-position bar (top or bottom) showing S&P 500,
  DJIA, Nasdaq with value + colored change, fed from `latest.key_metrics`.
- Desktop-only: hidden below `md` breakpoint (`hidden md:flex`). Add body padding so it
  doesn't overlap content. Rendered from `app/page.tsx` with the latest entry.

### Feature 3 — Market-vs-macro explainer
- New column `macro_entries.market_commentary text not null default ''`.
- In `/api/generate`: after building the entry, fetch the prior ~30 entries
  (dates, `macro_score`, `raw_signals`, index closes from `key_metrics`), call Claude
  with a prompt that contrasts index movements (week-over-week and month-over-month)
  against the macro-score trajectory, and store the commentary on the new row.
- New `components/MarketExplainer.tsx` renders `latest.market_commentary`.

## Open Questions
- Bar placement (top vs bottom) and whether to include % change as well as point change —
  resolve during BUILD.
- Whether to surface the schema-version seam visually on the trend chart — defer; not MVP-critical.

## Success Criteria
- New daily rows store 6 separate signals + `schema_version = 2`; `daily_scores_v`
  returns clean numeric rows.
- Desktop shows a persistent S&P/DJIA/Nasdaq bar; mobile is unaffected.
- Each new day's entry carries LLM commentary contrasting index moves vs macro scores,
  visible on the dashboard.
- Existing functionality (legacy rows, trend chart, chat) keeps working.

## Build Order
1. F1 — data model + scoring + prompt + view (foundation).
2. F3 — explainer (depends on F1 series).
3. F2 — floating ticker (independent; can parallel).

  over a quick column add. The seam matters more than the split.

  three independently shippable pieces with a clear dependency order.
